Atributo multivalorado

Vários telefones exigem uma relação própria

Na Aula 04, o requisito dizia que um usuário possui um ou mais telefones. O DER pode representar TELEFONE como atributo multivalorado. No modelo relacional, cada valor precisa ocupar uma ocorrência própria.

O que a nova relação significa?

Cada linha de TELEFONE_USUARIO representa um telefone de um usuário. A combinação (id_usuario, telefone) pode identificar cada ocorrência e evita repetir o mesmo telefone para o mesmo usuário.

Entidade fraca

A chave da proprietária passa a fazer parte da identificação

Para observar esse caso, vamos acrescentar uma pequena necessidade ao domínio de reserva de salas: além de registrar as reservas realizadas, o sistema também precisa organizar as faixas de agenda disponíveis de cada sala, registrando a data, o horário inicial e a situação de cada faixa.

De onde surge FAIXA_AGENDA?

Surge justamente dessa nova necessidade de controlar a agenda de cada sala. Uma ocorrência como 10/09 · 19:00 não identifica uma faixa de forma global, porque duas salas diferentes podem possuir uma faixa no mesmo dia e horário. A faixa só faz sentido quando sabemos a qual SALA ela pertence.

Por isso, FAIXA_AGENDA depende de SALA para ser identificada. A combinação de data e hora_inicio distingue uma faixa apenas dentro de uma sala específica; consequentemente, id_sala também precisa participar da identificação da relação resultante.
